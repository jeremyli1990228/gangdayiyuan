# 港大医院管理系统 - 新功能设计方案

## 一、项目概述

### 1.1 项目背景
基于现有港大医院管理系统，新增投诉管理、移动端H5集成、数据统计升级等20项新功能需求，以满足医院投诉处理、满意度调查、数据统计分析等业务场景。

### 1.2 技术栈
- 前端框架：Vue 3 + Vite
- 路由管理：Vue Router
- 状态管理：Pinia（新增）
- UI组件：自定义组件 + Element Plus（新增）
- 移动端：响应式H5页面
- 图表库：ECharts（新增）

---

## 二、投诉管理模块设计

### 2.1 模块概述
投诉管理模块包含电脑端和移动端（H5）两部分，实现投诉建议的全流程闭环管理。

## 七、自动保存功能

### 7.1 工单填写自动保存
**技术方案**：
- 定时保存：每2分钟自动保存
- 触发条件：表单内容有变化
- 保存位置：草稿箱/临时存储
- 提示方式：顶部轻提示"已自动保存"

### 7.2 实现细节
```javascript
// 自动保存逻辑
let autoSaveTimer = null
let hasChanges = false

// 监听表单变化
watch(formData, () => {
  hasChanges = true
}, { deep: true })

// 启动自动保存
const startAutoSave = () => {
  autoSaveTimer = setInterval(() => {
    if (hasChanges) {
      saveDraft()
      hasChanges = false
    }
  }, 2 * 60 * 1000) // 2分钟
}

// 页面离开前保存
onBeforeRouteLeave(() => {
  if (hasChanges) {
    saveDraft()
  }
})
```

```
├── 邮件主题（自动生成，可修改）
├── 改进措施内容（富文本编辑器）
├── 附件上传
└── 发送按钮
```

## 十七、闭环流程设计

### 17.1 流程节点
```
投诉提交
    ↓
专人接诉核实
    ↓
反馈（短信/公众号通知投诉人，明确答复时间）
    ↓
科室处理人处理
    ↓
处理结果反馈
    ↓
结果核实
    ↓
结案归档
```

### 17.2 各节点功能
| 节点 | 操作人 | 功能 |
|-----|-------|------|
| 投诉提交 | 投诉人 | 提交投诉信息 |
| 接诉核实 | 专人 | 核实投诉有效性，分配处理人 |
| 反馈通知 | 系统 | 自动发送受理通知 |
| 科室处理 | 科室处理人 | 处理投诉，填写处理结果 |
| 结果反馈 | 处理人 | 反馈处理结果给投诉人 |
| 结果核实 | 专人 | 核实处理结果，满意度调查 |
| 结案归档 | 专人 | 归档案件 |

## 二十、数据库表设计（建议）

### 20.1 投诉反馈表
```sql
CREATE TABLE complaint_feedback (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  submitter_name VARCHAR(100),        -- 提交人姓名
  category_id BIGINT,                 -- 分类ID
  feedback_type_id BIGINT,            -- 反馈类型ID
  description TEXT,                   -- 问题描述
  status TINYINT DEFAULT 0,           -- 状态：0待处理 1处理中 2已处理 3已评价
  submit_time DATETIME,               -- 提交时间
  end_time DATETIME,                  -- 结束时间
  handler_id BIGINT,                  -- 处理人ID
  handle_time DATETIME,               -- 处理时间
  handle_result TEXT,                 -- 处理结果
  rating INT,                         -- 评价星级
  rating_content TEXT,                -- 评价内容
  patient_name VARCHAR(100),          -- 患者姓名
  patient_no VARCHAR(50),             -- 病人号
  contact_phone VARCHAR(20),          -- 联系电话
  create_time DATETIME DEFAULT NOW(),
  update_time DATETIME DEFAULT NOW() ON UPDATE NOW()
);
```

```sql
CREATE TABLE feedback_type (

  create_time DATETIME DEFAULT NOW(),
  update_time DATETIME DEFAULT NOW() ON UPDATE NOW()
);
```

## 二十二、风险与注意事项

### 22.1 技术风险
1. 移动端H5兼容性问题 - 需测试多机型
2. 自动保存频繁请求 - 需做防抖处理
3. 大数据量统计性能 - 需做分页和缓存

### 22.2 业务风险
1. 历史数据迁移 - 需做好数据备份
2. 权限配置复杂 - 需充分测试
3. 闭环流程变更 - 需用户培训

### 22.3 建议
1. 分阶段上线，先核心后优化
2. 充分测试移动端兼容性
3. 做好用户培训和文档
4. 建立反馈渠道持续优化
